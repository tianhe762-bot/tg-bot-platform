# 更新记录

## v2.0.3

- tg_bot 增加单实例锁（flock），防止多个 bot 进程同时轮询 Telegram 抢消息
- `/status` 汇报中加入“机器人版本”，一眼可判断 bot 是否运行最新代码
- 部署规范：模块/命令文件变更后必须 `systemctl restart tg_bot.service`（模块在启动时加载）


## v2.0.2

- 修复 /switch 切换后旧连接仍走旧节点的问题：切换成功后自动关闭现有连接，全部流量立即以新节点重连
- /status 与 /mihomo 的当前节点改为取“最新连接”的链路，避免被切换前建立的旧连接干扰显示


## v2.0.1

- 修复节点切换“显示成功但未生效”：路由联动改为从真实连接链路找汇聚组（如 节点选择）切换，不再依赖结构识别主组
- 切换后校验生效节点，未生效时如实提示，不再谎报成功


## v2.0.0

- 新增看门狗管理：`/watchdog` 命令（菜单/回复数字切换）与 `tg-bot` 面板（14 看门狗管理），注册表可扩展多个看门狗
- 新增 ShellCrash 自愈看门狗：开机自启失败自动重建配置并重启，恢复/失败推送 Telegram（systemd timer 每 2 分钟）
- 新增国内推送兜底：Telegram 不可达时自动转推企业微信 / Server酱（面板 15 配置）
- 新增机械硬盘休眠支持：hdparm apm/standby（10 分钟停转）+ udev 持久化
- 部署流程：自动生成 watchdogs.conf 并启用看门狗 timer；UPS 断电告警增加国内兜底


## v1.8.1

- `/switch` 只允许切换当前可用节点：切换前对命中的节点实测延迟，≤800ms 才允许切换
- 不可用（超时/不通）的节点即使名称正确也会被拒绝，并提示从 `/mihomo` 可用列表选择


## v1.8.0

- Mihomo 功能全面去组名化：不再依赖任何组名/配置结构，换订阅、换主机、换规则都不影响
- `/mihomo` 平铺列出全部最底层节点与测速，不出现任何组名
- `/status` 通过真实流量链路（/connections）显示当前节点
- `/switch` 按真实链路或结构自动定位目标组，切换后主组自动联动生效


## v1.7.1

- `/switch` 增加模糊匹配：节点名丢失国旗前缀等也能自动匹配唯一节点并切换
- 多个候选时列出完整节点名供选择，未找到时提示从 `/mihomo` 复制完整名称


## v1.7.0

- `/mihomo` 改为按区域组显示节点与测速（如 香港节点/美国节点/日韩节点/台湾节点/新加坡节点/高级节点）
- 修复内置 REJECT-DROP 幽灵节点导致切换报“未找到该节点”的问题
- 修复主组误选内置 GLOBAL 的问题，切换自动定位到当前手动选择组


## v1.6.0

- 新增 `/ports`：自动列出 Docker 容器、非 Docker 程序（ss 扫描）与手动配置的服务端口，并生成局域网访问地址
- 新增配置项 `PANEL_SERVICES`：手动补充未自动识别的服务（名称=端口）


## v1.5.0

- `/status` 显示 CPU 使用率百分比与温度，并集成网卡与网络流量
- 移除 `/network`、`/traffic`、`/cpu24`、`/mem24`、`/network24`、`/disk_history`、`/logs` 命令
- `/help` 精简并新增切换节点模板
- 修复 `/status` 中 Mihomo 显示上层节点组名的问题，改为显示最底层节点


## v1.4.0

- `/mihomo` 改为只显示最底层节点与测速（连通且 ≤800ms，按延迟升序）
- `/update` 先显示当前版本与最新版本，确认后再升级机器人
- `/switch` 切换成功后显示新节点延迟
- `/help` 重写：每个命令都附带功能说明


## v1.3.0

- `/status` 的 Mihomo 部分改为汇报当前节点与延迟，未开启时显示“未开启”
- `/mihomo` 改为查看可用节点：并行测速，只显示连通且延迟 ≤800ms 的节点
- 新增 `/switch 节点名` 命令切换代理节点


## v1.2.0

- `/status` 全面升级：自动检测主机名和系统版本
- 运行时间、CPU 负载、内存使用率展示更直观
- 新增 Docker 容器列表展示
- 移除 `/cpu`、`/memory`、`/disk`、`/docker` 命令，统一由 `/status` 查看
