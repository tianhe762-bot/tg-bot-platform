# 我的第一台小主机：从到手到变成家庭服务器

> 一台升腾（Centerm）AI945-5 迷你主机的完整折腾记录：拆机换硅脂、装 Debian、部署代理/组网/机器人/Docker 全家桶，最后配上 UPS 断电保护。按真实操作顺序写成教程，方便后来人照着做。

---

## 前言

这是我的第一台小主机。它是一台退役的瘦客户机/迷你主机，硬件老但安静、省电，非常适合当家庭服务器：跑网盘、相册、代理、面板和各种自动化。这篇文章按我实际操作的顺序记录每一步做了什么、为什么做、怎么验证，既是教程也是总结。

## 一、硬件与到手折腾

### 1.1 配置一览

| 部件 | 配置 |
| --- | --- |
| 整机 | 升腾 Centerm AI945-5（H81 芯片组，迷你主机/瘦客户机） |
| CPU | Intel Core i3-4330 @ 3.50GHz（Haswell，2 核 4 线程，L3 4MB） |
| 内存 | 原装 4GB DDR3-1600 SODIMM（双电压 1.35/1.5V） |
| 系统盘 | Vaseky V800 64G SSD（SATA） |
| 数据盘 | 三星 ST320LM001 320G 2.5 寸机械盘（SATA） |
| 核显 | Intel HD 4600 |
| 网卡 | Realtek RTL8111/8168 千兆 |
| 扩展 | 4 口 PCIe 串口卡、HD Audio + HDMI 音频 |

### 1.2 拆机：两个重要发现

到手第一件事是拆机。发现两个问题：

**① 内存其实只能插一条。** 主板（DMI）虽然写着支持 2 个内存插槽、最大 16GB，但升腾实际阉割掉了一条——机箱里只有一个可用的 SO-DIMM 插槽。也就是说双通道没戏，**只能插一条内存**。原装是 4GB，于是我决定把这条 4GB 卖掉，换一条 **8GB DDR3-1600 SO-DIMM 单条**（i3-4330 原生支持 DDR3-1600，8GB 是这台机器最划算的容量）。

**② 散热硅脂已经干巴了。** 拆开散热器一看，原厂硅脂完全干裂，直接影响 CPU 温度。顺手清掉旧硅脂，重新涂了新的导热硅脂，再装回去。这台机器之后一直很安静、温度正常，这一步很值。

## 二、安装 Debian Linux

系统选的是 **Debian GNU/Linux 13 (trixie)**——稳定、轻量、社区资料多，适合长期跑服务。

### 2.1 分区思路（关键）

```text
64G SSD  → 系统盘 /（系统、程序、Docker 根目录）
320G HDD → 数据盘 /mnt/photos（相册、文件等大体积数据）
```

系统装在 SSD 上，所有大体积数据都放 HDD，避免小 SSD 被照片/文件塞满。

### 2.2 安装后的基础设置

```bash
# 更新系统
apt update && apt upgrade -y

# 安装 sudo（后续提权用）
apt install -y sudo

# 新建日常用户（非 root，日常操作都用它）
adduser <你的用户名>
usermod -aG sudo <你的用户名>
```

之后所有操作都通过 SSH 远程进行。

## 三、第一步：SSH 远程管理

服务器放家里角落，不可能天天接显示器，所以第一件事就是**把 SSH 开起来**，让所有后续操作都能远程完成。

```bash
systemctl enable --now ssh
```

验证：

```bash
# 在另一台电脑上
ssh <你的用户名>@<局域网IP>
```

同时建议：

- 关闭 root 直接登录（`PermitRootLogin no`），日常用普通用户 + `su`/`sudo`；
- 有条件就换密钥登录，不依赖密码。

## 四、第二步：代理（ShellCrash / Mihomo）

这台机器还要承担“代理”的职责，所以第二步就装了 **ShellCrash + Mihomo（Clash Meta 内核）**。

- 绑定订阅（机场），生成分流规则；
- 设置每天自动更新订阅的定时任务；

### 验证

```bash
# 用代理访问外网测试（例如 curl -x 代理地址 https://www.gstatic.com/generate_204）
```

> 踩坑：服务器重启后 `/tmp` 被清空，ShellCrash 的配置和内核文件会丢失导致开机失败。解决办法：手动执行它的启动前脚本（`bfstart.sh`）重建配置后 `systemctl restart shellcrash`。**教训：重启后要检查代理是否正常。**

## 五、第三步：Tailscale 异地组网

家里局域网之外也想安全访问这台机器，于是装了 **Tailscale**：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
```

做完之后：

- 这台机器有了一个稳定的 Tailscale 虚拟 IP（`100.x.x.x`）；
- 在外面也能直接 SSH、访问面板，相当于免费的内网穿透，且默认加密；
- 即使家里没有公网 IP 也能连回来。

验证：另一台设备加入同一 Tailscale 网络后 `ping 100.x.x.x` 或直接 SSH。

## 六、第四步：Telegram 机器人（远程管理中枢）

服务越来越多之后，我决定给这台机器装一个 **Telegram 机器人**：在 Telegram 里发消息就能查看状态、切换节点、备份、更新，甚至远程开关机。项目开源在 GitHub，一键安装。

### 安装

```bash
curl -fsSL https://raw.githubusercontent.com/tianhe762-bot/tg-bot-platform/main/install.sh | bash
```

按提示填入：

- Telegram Bot Token（找 @BotFather 创建）；
- 管理员 Telegram ID；
- WOL 目标 MAC（可选）；
- Mihomo API 地址。

### 功能（当前版本 v2.0.0）

| 命令 | 功能 |
| --- | --- |
| `/status` | 系统状态总览（CPU/温度/内存/磁盘/网络/Docker/Mihomo 当前节点） |
| `/ports` | 列出所有服务的局域网访问端口 |
| `/mihomo` | 全部最底层节点测速（只显示可用节点，≤800ms） |
| `/switch 节点名` | 切换代理节点（只允许切当前可用节点，切完报延迟） |
| `/wake` | 局域网设备远程开机（WOL） |
| `/backup` | 数据与配置备份 |
| `/update` | 版本检查与自动更新（保留配置、失败自动回滚） |
| `/reboot` `/shutdown` | 重启/关机（需二次确认） |
| `/help` | 帮助与切换节点模板 |
| `/watchdog` | 看门狗管理（开启/关闭） |

机器人还带**自动监控报警**（CPU/内存/磁盘/Docker 异常时主动推送）和定时健康检查。

v2.0.0 起新增：**看门狗管理**（`/watchdog` 命令 + `tg-bot` 面板双入口）、**ShellCrash 自愈看门狗**（开机自启失败自动恢复并通知）、**国内推送兜底**（Telegram 不可达时自动转推企业微信 / Server酱）、**机械硬盘 10 分钟停转休眠**。

> 💡 这个机器人项目**完全开源**，代码托管在我的 GitHub 仓库：[tianhe762-bot/tg-bot-platform](https://github.com/tianhe762-bot/tg-bot-platform)，想用、想改的可以直接去看。

## 七、第五步：Dockge（容器栈管理面板）

后面要装一堆 Docker 服务，于是先装了 **Dockge**——一个 Docker Compose 栈管理面板，可以在网页上启停、看日志、编辑 compose。

## 八、第六步：装里面的所有 Docker 服务

### 8.1 alist —— 文件列表/网盘

第一个跑起来的服务，把硬盘上的文件变成可通过网页/WebDAV 访问的网盘。数据目录挂载在 `/etc/alist`。

### 8.2 Immich —— 家庭相册

用官方 docker-compose 部署，照片库、AI 模型缓存都放在数据盘 `/mnt/photos/immich`。自带人脸识别、AI 搜索、时间线，是目前自托管相册的首选。

> 踩坑：immich 的 compose 目录在 `/opt/immich` 和 `/mnt/photos/immich` 各有一份，运行中的容器路径是混的（服务端用后者、数据库用前者）。整理时保持两份路径不变，避免数据错位。

### 8.3 Lucky —— DDNS/反向代理/端口转发

一个全能小工具：DDNS 动态域名、反向代理、端口转发、计划任务等，后续做公网访问用得上。

### 8.4 把旧容器全部迁进 Dockge

服务多了以后，**把 alist、immich 等全部“迁进” Dockge 统一管理**：

1. 先停掉全部容器；
2. 把 compose 文件整理到 `/opt/stacks/<栈名>/`（immich 用原来的 compose+.env，alist 用工具从运行中容器自动生成 compose）；
3. 逐个 `docker compose up -d` 重新拉起，数据卷全部保留；
4. 验证全部 healthy 后，Dockge 页面里就能看到所有栈。

现在所有容器的启停、日志、编辑都在 Dockge 网页上完成。

## 九、最后一步：UPS 断电保护

> 这是整套配置里我认为最值得做的一步。

给主机配了一台 USB 接口的 UPS，系统用 **NUT（Network UPS Tools）** 管理：

```text
驱动：blazer_usb（检测到 USB ID 0665:5161，Megatec/Q1 协议）
监控：upsd + upsmon（本地回环监听，不对外暴露）
```

### 工作逻辑

```text
市电中断
   ↓ UPS 发出 ONBATT 信号
   ↓ 主机通过 Telegram 通知：「市电中断，已切换 UPS 供电，30 秒后自动关机」
   ↓ 30 秒后自动 poweroff
市电恢复（若主机仍在运行）
   ↓ 发送「市电已恢复」通知
```

### 关键配置

```ini
# /etc/nut/ups.conf
[ups]
    driver = blazer_usb
    port = auto
    vendorid = 0665
    productid = 5161
    desc = "Main UPS"
    allow_killpower = yes
    offdelay = 12

# /etc/nut/upsmon.conf（节选）
MONITOR ups@localhost 1 monuser <密码> primary
SHUTDOWNCMD "/sbin/poweroff"
POWERDOWNFLAG /run/nut/killpower
NOTIFYCMD /usr/local/bin/ups_alert.sh
NOTIFYFLAG ONBATT SYSLOG+EXEC
NOTIFYFLAG ONLINE SYSLOG+EXEC
```

通知脚本逻辑：收到 `ONBATT` → 发 Telegram 通知 → 等待 30 秒 → 通过 `upsmon -c fsd` 触发 **FSD 关机**（配合 `allow_killpower` 让 UPS 切断输出，市电恢复后 UPS 会自动重新供电，主机也能配合 BIOS“来电自启”）；收到 `ONLINE` → 发恢复通知。通知走代理优先、失败自动直连（和机器人同一套网络策略）。

实测：`ups.status=OL`（市电）、电池 100%、输入电压 235V；通知链路已用测试消息验证通过。

> 小坑：这个 UPS 的 USB HID 描述符是厂商自定义页（不是标准电源设备），usbhid-ups 认不出来，换成 `blazer_usb` 驱动后一切正常；另外还补了一条 udev 规则把 USB 设备权限放给 nut 组，并安装 sudo 用于触发 FSD 关机。

## 十二、踩坑记录

1. **升腾阉割了第二条内存槽**：看起来双通道，实际只能插一条；
2. **原厂硅脂干巴**：拆机换硅脂，散热立刻正常；
3. **Immich 双 compose 目录**：路径混用，迁移时保留原路径不动；
4. **ShellCrash 开机自启失败**：原因是开机前忘了插网线，开机后一直连不上网，代理自启没成功；接上网线后手动重启服务即恢复；
5. **Windows 打包带回车符**：Windows 打出的压缩包在 Linux 会产生带 `\r` 的目录/文件，需要统一转 LF；
6. **节点切换“找不到节点”**：早期按组名写逻辑，换订阅就失效；后来彻底重写成“不依赖任何组名”的通用方案（真实流量链路 + 结构识别），并限制只切当前可用节点；
7. **UPS 不是标准 HID 电源设备**：需要 `blazer_usb` 驱动 + udev 放行权限，并配合 sudo 触发断电关机。

## 结语

一台退役小主机，拆开换条内存和硅脂，装个 Debian，跑起代理、组网、Telegram 机器人和 Docker 全家桶，再配上 UPS——就是一个称职的家庭服务器。下一步计划：8GB 内存到位、配公网 DDNS、把备份推到异地。

> 💡 **给后来人的建议**：如果重来一遍，我会**先装 Docker 和 Dockge**，然后直接在 Dockge 里创建/安装后面的所有服务（alist、Immich、Lucky 等），避免“先手动装再迁移”的折腾——所有栈从一开始就在面板里，启停、日志、升级都统一。
